0. 读代码路线（建议顺序）

目标：1 天内能跟完「配置 → Tick → 生成回复 → 发送」全链路，知道改 bug 该动哪一层。

  1. 定边界 · AGENTS.md + tasks.md§P 先搞清红线（不编造事实、白名单、升级人工）和当前冲刺目标，再读实现。
  2. 看配置真相 · config/cs-runtime.json + packages/runtime-config/index.js 白名单、autoSend、knowledge.mode、systems.order、onMiss 都从这里来；schema 在 runtime-config。
  3. 跟一条 Tick · apps/edge-worker/cs-watch.js（搜 async function tick → processMeituan） 核心在这一文件：扫列表 → 进会话 → 气泡待回 → claim → generateReply → send。
  4. 跟回复决策 · 同文件搜 generateReply，再读 order-lookup.js、kb-retrieve.js 查单 / 知识库 / LLM / 澄清模板的优先级都在这里。
  5. 看中台怎么被调用 · brain/rag-service/src/routes/api.ts + rag/hybrid-retriever.ts 边端只 HTTP；向量/Hybrid 在 :8787，不在 cs-watch 里直连库。
  6. 看配置台怎么改运行时 · apps/console/app/page.js + api/config/route.js UI 写回 cs-runtime；当前本机也可能是 kb-admin-server.js 托管同一套 admin 页。
  7. 看启动与产物 · scripts/Start-All.ps1 + memory/cs-watch.log / memory/chat-trace.jsonl 联调时日志标签（MEITUAN / KB_HIT / ORDER_LOOKUP）是最好的调试入口。

1. 架构分层（一眼看懂）

边端 Edgeapps/

坐席机：浏览器巡检、发消息、本地降级检索、查单 Adapter。

  • apps/edge-worker — cs-watch / order / kb
  • apps/desktop — 「智能客服」一体端（Electron）
  • apps/console — Next 配置台（可选）
  • OpenClaw 橙框浏览器 + CDP

中台 Brainbrain/ + infra/

知识中台：向量库、Hybrid 检索、知识卡编译。边端只 HTTP。

  • brain/rag-service — :8787
  • infra/ — Postgres/pgvector + Redis
  • 生产可独立远程部署

配置 Configconfig/ · .env

白名单、平台开关、查单、知识库 mode、autoSend。

  • config/cs-runtime.json — 热读主配置
  • 根 .env — 路径 / RAG_BASE_URL
  • brain/.env — DB / Embedding 密钥
┌─ Start-All.ps1 ─────────────────────────────────────────────┐ │ Ensure-Infra → rag-service(:8787) → console 或 kb-admin(:18790) │ │ → OpenClaw gateway + 浏览器(CDP:~18800) → cs-watch 巡检 │ └──────────────────────────────────────────────────────────────┘ │ │ ▼ ▼ 边端 Edge 中台 Brain cs-watch ──CDP──▶ 美团/抖音 IM rag-service ──▶ Postgres │ ▲ └── HTTP retrieve ─────────────┘ └── CDP ──▶ 自有 SaaS 查单页（systems.order）

2. 启动流程（谁先谁后）

  1. scripts/Ensure-Infra.ps1 — 对 DATABASE_URL（Supabase）执行 init-db.sql，无 Docker
  2. 启动 brain/rag-service（健康检查 /health）
  3. 启动配置台：优先 Next apps/console，失败回退 scripts/kb-admin-server.js（同端口 :18790）
  4. 启动 OpenClaw gateway + 受控浏览器（CDP 常见 18800）
  5. 启动 apps/edge-worker/cs-watch.js（单实例锁 memory/cs-watch.lock）

注意：只跑 npm run edge 不会起浏览器。日常联调用 npm start。 JS 改动需重启 watch（或 npm run edge:dev）；JSON 配置每 tick 热加载。

3. 客服主链路（每个 Tick）

tick(cfg, state) ├─ 合并磁盘 state.processed（尊重 _clearedFps，防指纹复活） ├─ processMeituan │ ├─ scan 会话列表（iframe DOM） │ ├─ pickTargets：白名单会话全部纳入（进线后看气泡，不信列表预览） │ ├─ 短 TTL 冷却（刚确认无待回则跳过，有未读/待回复仍进） │ ├─ open 会话 → dismiss 智能推荐 → readThread（左右气泡） │ ├─ listUnreplied：最后一条客服之后的顾客气泡（按时间，最多 5 条） │ ├─ 逐条：claim → generateReply（带近 5 条上下文）→ send → settle │ └─ 若 openWork（claim-race / 发送失败）→ 本轮不切抖音 ├─ [可选] waitBeforeSwitchTabMs └─ processDouyin（同构：list / open / 连续未回逐条回 / send）

4. generateReply 决策顺序

  1. 高风险（退款/赔偿/差评）→ 升级话术，不自动承诺
  2. 查单 order-lookup.tryHandle
    • 硬特征：订单号 / 手机号 → 直查
    • AI 判意图（主路径）；AI 判否不被关键词覆盖
    • AI 失败才规则兜底；FAQ/到店自送不当搜单
  3. 门店地址 / 到店：意图命中后固定检索「门店地址」卡片（禁止 LLM 编地名）
  4. 知识库 kb-retrieve.retrieve
    • mode=remote → 中台 Hybrid；失败可 fallbackLocal
    • 命中 + preferKbAnswer → 直发
    • 事实题未命中 → 禁止乱编（clarify / onMiss）
    • 闲聊 → 可走 LLM（带近 5 条上下文；外发剥离「顾客/客服」标签）

9. 排障速查

  • /project-map 404 → 确认 :18790 是 console 还是 kb-admin-server；后者需有 project-map 路由。
  • 无自动回 + claim-race → 双实例或指纹复活；查 lock / state。
  • 政策问被查单 → 看 ORDER_LOOKUP via=。
  • ECONNREFUSED :18800 → 浏览器/CDP 未起，重跑 npm start。
  • KB_REMOTE_FAIL / 地址问澄清 → 中台 :8787 或店址意图未走到「门店地址」检索。
  • 改了 JS 不生效 → 重启 watch 或用 edge:dev。
